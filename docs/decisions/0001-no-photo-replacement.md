# 0001. 사진 변경 금지

**날짜**: 2026-05-24
**상태**: 채택 (Accepted)
**관련 PRD**: `06-stamp-detail.md` §3.4

## 컨텍스트

사용자가 등록한 사진을 나중에 다른 사진으로 바꿀 수 있게 할지 결정 필요했다. 일기 앱으로서 "그날의 진짜"를 기록한다는 정체성과, 사용자가 결과물에 만족하지 못해 수정하고 싶어하는 욕구 사이의 균형이 쟁점.

## 결정

**사진은 한 번 등록하면 바꿀 수 없다. 변경하려면 삭제 후 재등록만 가능.**

크롭, 메모, 감정, 스타일은 자유롭게 수정 가능. 사진(Blob)만 불가.

## 이유

1. **자기검열 방지** — 그날의 진짜 사진을 미래의 내가 덮어쓰지 않게. SNS에서 "예쁘게 보이는 사진"으로 바꾸려는 충동을 차단.
2. **기록의 무게감** — 사진은 "사실 (그날 거기 있었다)", 메모/감정/스타일은 "해석 (어떻게 받아들였나)". 표현은 시간 따라 다듬어도 되지만 사실은 그대로.
3. **일기로서의 정체성** — 인스타그램/카메라 롤이 아니라 일기다.

## 결과

- 상세 화면 (`/stamp/[date]`)에 "사진 변경" 버튼 없음.
- `updateStamp` 함수 시그니처: `Partial<Pick<Stamp, 'memo'|'mood'|'moodVisible'|'style'|'crop'>>` — `photoBlob`을 **type-level에서 차단**.
- 크롭 재조정만 별도 함수 `recropStamp` (originalPhotoBlob에서 재추출).
- 사용자 요청 시 안내: `"사진은 바꿀 수 없어요. 새로 등록하려면 우표를 삭제해주세요."` (PRD §10 §5.2).
- `prd-guardian` 에이전트가 정기적으로 위반 패턴 (`<input type="file">`가 등록 화면 외에 있는지) 검사.

## 대안

- **모두 수정 가능**: 인스타그램 같은 가벼움. 하지만 자기검열 위험 ↑, "사진 = 기록의 핵심"이 사라짐.
- **모두 수정 불가**: 너무 경직. 메모 오타도 못 고침.
- **선택: 사진만 잠금, 나머지 자유** ✅ — 사실/해석 분리 명확.

## 재검토 시점

v2.0 (외부 공개 검토) — 일반 사용자도 같은 정책을 받아들일지 본인 사용 1개월 후 평가.
