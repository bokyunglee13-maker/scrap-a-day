# 0005. iOS Safari ITP 7일 IndexedDB 삭제 대응

**날짜**: 2026-05-24
**상태**: 채택 (Accepted) — 4단계 완화 전략 적용. v1.1 클라우드 백업이 최종 해결.
**관련 PRD**: `15-mobile-first.md` §15.5.1, `11-failure-modes.md` §9.5, `14-roadmap.md` v1.1 #1

## 컨텍스트

**문제 (이 앱의 가장 큰 데이터 위험)**:
iOS Safari는 사용자가 **7일 이상 사이트를 미방문** 시 IndexedDB를 통째로 자동 삭제한다 (Apple Intelligent Tracking Prevention, 2020+). 매일 쓰는 일기 앱이지만 휴가/출장/병원 등으로 7일+ 안 쓰면 **모든 우표 데이터 손실**.

iOS 사용자 비율이 한국에선 약 30%+, 모바일 우선 앱 (PRD §15)이라 무시 불가.

## 결정

**4단계 완화 전략** (우선순위 순):

### 1. PWA "홈 화면에 추가" 적극 권유 (Phase 5 구현)
- 첫 방문 + 일정 사용 후 메인 상단 안내 배너 노출.
- 홈 화면 설치 = Apple ITP 정리 대상에서 **제외** (공식 동작).
- 메시지: `"홈 화면에 추가하면 데이터가 더 안전해요"`.
- 1회 dismiss 기억 (Settings).

### 2. 자동 백업 알림 (Phase 5 구현)
- 마지막 백업 (`settings.lastBackupAt`)이 N일 이전이면 메인 상단 배지 / 토스트.
- N = 5일 (잠재 ITP 임계점 7일보다 안전 마진).
- 메시지: `"백업해두면 안심이에요"`.

### 3. 로컬 백업 1탭 (Phase 5 구현)
- 설정 → 백업 화면에서 JSON + ZIP을 각 한 번의 탭으로 받기.
- 진행 상태 표시 (사진 100MB+ 가능).

### 4. v1.1 — 옵션 클라우드 백업 (Supabase) 1순위
- 옵션 로그인 후 사용자 명시 동의 시.
- ITP의 근본 해결 (서버 백업).
- PRD §14 v1.1 로드맵 #1 (다른 v1.1 항목보다 우선).

## 이유

1. **데이터 손실은 일기 앱의 가장 큰 죄** — 우표 한 장 = 그날의 사실. 잃어버리면 복구 불가.
2. **PWA 설치 = 가장 효과적 완화** — Apple 공식. 사용자 동작 한 번으로 ITP 무력화.
3. **자동 알림 = 사용자 인지 강제** — 사용자는 ITP를 모름. 시스템이 백업 시점을 알려야 함.
4. **MVP는 로컬** (ADR 0004) — 클라우드는 v1.1까지 못 기다림? 4단계 완화로 충분 가정.

## 결과

- PRD §15.5.1 정책 명문화.
- PRD §11 §9.5 모바일 특유 실패 모드 — iOS ITP 🚨 표기.
- ROADMAP §5.11 (Phase 5) 모바일 우선 마무리 작업: PWA 설치 배너 + 자동 백업 배지.
- `lib/settings.ts` `lastBackupAt` 필드 + `daysSinceBackup` 헬퍼.
- `lib/backup.ts` `recordBackup()` 호출 — 모든 백업 성공 시 자동 업데이트.

## 대안

- **클라우드 백업을 MVP에 포함**: 가장 안전. 그러나 MVP 범위 ↑, 로그인 마찰 + 프라이버시 우려 (ADR 0004).
- **알림만 (PWA 권유 안 함)**: 효과 부족. 사용자가 알림 무시하면 손실.
- **PWA 권유만 (자동 백업 알림 안 함)**: 설치 안 한 사용자는 무방비.
- **4단계 다층 방어** ✅ — 어느 한 단계 실패해도 다음 단계가 보호.

## 재검토 시점

- 본인 사용 1개월 후 — 실제 ITP 발동 사례 있는지 (PWA 설치 안 한 상태로 7일 미방문 시도). 자동 백업 알림 효과 측정.
- v1.1 — 클라우드 백업 출시. 그때 ITP 위협 종결 → 1~3단계는 부가 보호로 남김.
