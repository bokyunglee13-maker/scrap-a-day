# 0002. 휴지통 30일 보관

**날짜**: 2026-05-24
**상태**: 채택 (Accepted)
**관련 PRD**: `07-trash-backup.md`, `11-failure-modes.md` §9.3.3 (비파괴 원칙)

## 컨텍스트

우표 삭제 시 즉시 영구 삭제할지, 휴지통을 둘지 결정 필요. 휴지통을 둔다면 보관 기간은?

## 결정

**삭제 시 즉시 영구 삭제 X. `deletedAt = new Date()`로 소프트 삭제 후 30일 보관. 30일 후 자동 영구 삭제.**

사용자는 언제든 휴지통에서 즉시 비우기 가능. 휴지통에서 복원 시 해당 날짜로 복귀.

## 이유

1. **비파괴 원칙** — 일기는 사용자의 소중한 데이터. 실수 한 번에 사라지면 안 됨.
2. **5초 토스트로는 부족** — "되돌리기" 토스트는 5초만 가능. 며칠 뒤 후회할 수도 있음.
3. **30일은 OS 표준** — macOS / iOS / Android 휴지통 모두 ~30일. 사용자 멘탈 모델과 일치.
4. **자동 정리는 필수** — 사용자가 휴지통 정리를 안 하면 데이터 누적. 자동으로 영구 삭제.

## 결과

- `softDeleteStamp(id)`: `deletedAt = new Date()` (영구 삭제 아님).
- `restoreStamp(id)`: `deletedAt = null` (단, 같은 날짜에 새 우표 있으면 `DUPLICATE_DATE`).
- `cleanExpiredTrash()`: 앱 로드 시 한 번 실행, 30일 지난 stamps 영구 삭제.
- 상세 화면 삭제 → 5초 "되돌리기" 토스트 → 그 후엔 휴지통 화면에서만 복원 가능.
- `permanentDeleteStamp(id)`: 사용자 명시 영구 삭제 경로.

## 대안

- **즉시 영구 삭제**: 실수 복구 불가. 데이터 손실 위험 ↑.
- **7일**: 너무 짧음. 휴가/병원 가는 동안 의도치 않게 영구 삭제.
- **무제한 보관**: IndexedDB 용량 누적, iOS Safari ITP 7일 정리 위험 증가.
- **30일** ✅ — OS 표준, 회복 시간 충분, 누적 부담 없음.

## 재검토 시점
