# 0004. 로컬 전용 저장 (MVP)

**날짜**: 2026-05-24
**상태**: 채택 (Accepted) — MVP. v1.1에서 옵션 클라우드 백업 추가 예정.
**관련 PRD**: `01-overview.md` (Non-goals: "클라우드 서비스가 아니다 (MVP)"), `15-mobile-first.md` §15.5.1 (iOS ITP 대응)

## 컨텍스트

데이터 저장 위치 결정. 클라우드 (Firebase / Supabase / 자체 서버) vs 로컬 (IndexedDB) vs 하이브리드.

## 결정

**MVP는 로컬 전용 (IndexedDB / Dexie).** 로그인 없음, 외부 서버 없음, 사용자 데이터가 기기 밖으로 나가지 않음.

v1.1에서 **옵션** 클라우드 백업 (사용자 명시 동의 후) 추가 예정.

## 이유

1. **개인 일기의 프라이버시** — 가장 사적인 기록. 어떤 서버도 안 거치는 게 최고 프라이버시.
2. **로그인 마찰 제거** — 일기는 매일 쓰는 도구. 로그인 한 번이라도 마찰이면 사용 빈도 ↓.
3. **MVP 범위 축소** — 백엔드 서버 = 추가 인프라/비용/유지보수. 본인 사용 검증 전엔 과투자.
4. **인증/보안 이슈 회피** — 서버 없음 = 인증 우회 / 데이터 유출 위험 0.

## 결과

- IndexedDB (Dexie.js) — 모든 데이터 (stamps, settings, errors, usage) 브라우저 로컬.
- 로그인 화면 없음.
- 외부 분석 / 추적 / 백엔드 API 호출 0건.
- 백업 = JSON + ZIP 사용자 다운로드 (수동).
- 사진 = Blob 그대로 IndexedDB 저장.

## 트레이드오프 (인지된 위험)

### 🚨 iOS Safari ITP 7일 자동 삭제 (PRD §15.5.1)
사용자가 7일 이상 미방문 시 IndexedDB 통째로 삭제됨 (Apple Intelligent Tracking Prevention). 매일 쓰는 일기 앱이지만 휴가/병원 등으로 7일+ 안 쓰면 모든 데이터 손실.

**MVP 완화**:
- PWA "홈 화면에 추가" 권유 (Phase 5) — 설치 시 ITP 정리 대상 제외 (Apple 공식 동작).
- 자동 백업 알림 (3~5일에 한 번) — 사용자에게 백업 받도록.
- JSON + ZIP 1탭 백업 — 가능한 한 마찰 줄임.

**v1.1 1순위**: 옵션 클라우드 백업 (PRD §14 로드맵).

### 기기 교체 시 마이그레이션
사용자 폰 바꿀 때: JSON + ZIP 백업 → 새 기기에서 가져오기. v1.1에서 가져오기 기능 추가 예정.

## 대안

- **클라우드 우선**: 데이터 안정성 ↑. 그러나 로그인 마찰 + 프라이버시 우려 + 인프라 비용.
- **로컬 + 자동 클라우드 동기화**: 양쪽 장점. 그러나 MVP에 과스코프.
- **로컬 only, 백업 수동** ✅ (MVP) — 단순, 빠름, 프라이버시 최고. ITP 위험은 PWA 설치 권유로 완화.

## 재검토 시점

- 본인 사용 1개월 후 — 데이터 손실 사고 횟수, 백업 빈도 측정.
- v1.1 시점 — 클라우드 백업 옵션 추가 (Supabase + 옵션 로그인).
