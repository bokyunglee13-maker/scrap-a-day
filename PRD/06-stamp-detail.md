# 06. 상세 화면 + 수정/삭제 정책

> 주 사용: **Phase 4**
> 🚨 **§3.4 사진 변경 금지 정책 — 절대 위반 금지**

---

## 라우팅

`/stamp/[date]` — 예: `/stamp/2026-05-24`

---

## 레이아웃

- 큰 우표 (화면 70% 정도, size `lg`)
- 날짜 (큰 글씨)
- 메모 (있으면)
- 감정 (있으면, ON/OFF 무관하게 본인은 볼 수 있음)
- 액션 버튼들 (아래 §3.2 참조)

---

## 3.1 인터랙션

| 액션 | 동작 |
|---|---|
| **메모/감정/스타일 수정** | 인라인 또는 다이얼로그, 수정 표시 없음 |
| **크롭 다시** | 같은 사진으로 cropper 다시 띄움 (사진 변경 X) |
| **이미지 저장** | PNG 다운로드 (모바일 Web Share API) |
| **삭제** | 확인 다이얼로그 → 휴지통으로 이동 |

---

## 3.2 액션 버튼

상세 화면 하단 또는 헤더에:

- `크롭 다시` — 같은 사진으로 크롭만 재조정
- `메모 수정`
- `감정 변경`
- `스타일 변경`
- `이미지 저장` — PNG 내보내기
- `삭제`

**없는 것**: `사진 변경` — 정책상 금지 (§3.4 참조)

---

## 3.3 수정 자유도

| 항목 | 수정 가능? | 이유 |
|---|---|---|
| **사진 자체** | ❌ | 자기검열 방지 (변경하려면 삭제 후 재등록) |
| **크롭 영역** | ✅ | 표현 방식이지 사실이 아님, 실수 교정 필요 |
| **메모** | ✅ | 자유, 수정 표시 없음. 해석은 시간 따라 진화 |
| **감정** | ✅ | 자유 |
| **감정 표시 ON/OFF** | ✅ | 프라이버시 설정 |
| **우표 스타일** | ✅ | 순수 디자인 선택 |

## 🚨 3.4 사진 변경 금지 정책 (절대 위반 금지)

### 정책
- 상세 화면에 "사진 변경" 버튼 **만들지 않는다**.
- "사진 다른 걸로 바꾸기" 기능 일체 제공 안 함.
- 변경하려면 **삭제 후 재등록**만 가능.

### 이유
1. **자기검열 방지**: 그날의 진짜 사진을 미래의 내가 덮어쓰지 않게.
2. **기록의 무게감**: 사진은 그날 거기 있었다는 "사실"이다. 한 번의 결정으로 끝.
3. **표현(크롭/메모/감정)과 사실(사진) 분리**: 표현은 시간 따라 다듬어도 OK, 사실은 그대로.

### 사용자 요청 시 응답
사용자가 "사진 바꿔달라" 요청해도:
- 정중히 거부 + 정책 안내 (메시지: 10-hook-messages.md §5.2 참조)
- "삭제 후 재등록"이 정식 절차임을 안내
- 절대 우회 경로 만들지 말 것 (예: "사진 모달 띄워서 새 파일 받기" 같은 것 X)

### `prd-guardian` 자동 차단
이 정책 위반이 의심되는 코드는 `prd-guardian` 에이전트가 자동 차단.

## 3.5 삭제 = 휴지통 (30일 보관)

상세는 `07-trash-backup.md` 참조. 핵심만:

- 삭제 시: 확인 다이얼로그 → 휴지통으로 이동 (`deletedAt = new Date()`)
- 토스트: "휴지통으로 옮겼어요" + "되돌리기" 버튼 (5초)
- 30일 후 자동 영구 삭제
- 휴지통에서 언제든 복원 가능

---

## 3.6 화면별 실패 처리

상세는 `11-failure-modes.md` §9.2.3 참조. 핵심만:

- 수정 저장 실패 → 원본 유지 + 폼에 변경사항 남김 + 재시도
- 삭제 실패 → 토스트 + 데이터 유지 (절대 어중간한 상태 X)
- 크롭 재조정 중 사진 소실 → "원본 사진을 찾을 수 없어요" 메시지
